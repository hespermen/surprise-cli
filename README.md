# SURPRISE.FM в терминале

Эфир, архив выпусков и своя библиотека — без браузера.

```bash
npm i -g "$(npm pack -s github:hespermen/surprise-cli)" && surprise radio
```

Выглядит длиннее обычного `npm i -g github:…` — и это не прихоть. На npm 10.x
короткая форма отвечает «added 1 package» и оставляет **пустой** каталог пакета:
команда появляется, но не запускается. Сбой при этом выглядит как успех, поэтому
здесь сразу тот путь, который работает везде. На npm 11 и новее короткая форма
тоже годится:

```bash
npm i -g github:hespermen/surprise-cli && surprise radio
```

## Установка

### Если раньше стоял `surprise-fm`

Пакет назывался так до переименования и ставил **ту же команду** `surprise`.
Два пакета не могут владеть одной командой: новый встанет, скажет «added 1
package», а `surprise` по-прежнему запустит старый. Обновление при этом выглядит
успешным и ничего не меняет.

```bash
npm rm -g surprise-fm
```

Проверить, что запускается сейчас:

```bash
surprise --version    # surprise-cli 0.2.0
```

Ответ без имени пакета (просто `0.1.0`) — это старая установка.

### `EEXIST: file already exists`

```
npm error code EEXIST
npm error path ~/.local/bin/surprise
npm error File exists: ~/.local/bin/surprise
```

Команду занимает шим старого пакета, и npm отказывается его перезаписывать —
правильно делает: под этим именем может стоять что угодно. `npm rm -g` его не
всегда снимает, если пакет переименовали: шим остаётся сиротой, без хозяина,
который бы за него отвечал.

```bash
ls -l ~/.local/bin/surprise    # посмотреть, куда он ведёт
rm ~/.local/bin/surprise
```

Путь берите из текста ошибки — префикс npm у всех свой.

### Сам пакет

Пакет — один самодостаточный файл (~250 КБ, только встроенные модули Node),
поэтому установка не тянет за собой дерево зависимостей.

Нужен **mpv** — он играет звук:

```bash
brew install mpv          # macOS
apt install mpv           # Debian/Ubuntu
winget install mpv        # Windows
```

Без mpv возьмётся `ffplay` из пакета ffmpeg, если он есть. С ним всё работает,
но хуже: перемотка перезапускает поток, громкость не меняется на лету, а позиция
считается по часам, а не от декодера. CLI об этом предупреждает при запуске.

## Первый запуск

При самом первом запуске плеер задаст три вопроса: язык, тема, вход. Потом
откроется сам и больше спрашивать не будет.

Язык спрашивается первым намеренно — всё, что показано дальше, написано на нём,
и выбирать тему по подписям на чужом языке неудобно. Тема применяется прямо во
время выбора: экран перекрашивается, пока ходишь по списку, так что решение
принимается по тому, что видно, а не по названию.

Вход можно пропустить: эфир играет и без аккаунта. Войти получится в любой
момент командой `/login`, а пройти настройку заново — `/setup`.

## Интерфейс

Запустите без аргументов — откроется многопанельный режим: разделы слева,
список справа, подробности под ним, плеер во всю ширину внизу.

```bash
surprise
```

Разделы и их порядок повторяют навигацию сайта — Эфир, Новое, Резиденты,
Авторы, Музыка, Моя коллекция, Избранное, Мои находки, Сохранённое, Подписки,
Поиск. Эфир включается сразу.

**Эфир — это поток.** Раздел «Эфир» показывает расписание для справки: что идёт
и что дальше. Запускать по нему архивные записи нельзя — нажимая Enter в эфире,
человек ждёт эфира, а не выпуска с начала.

**Карточки открываются внутрь.** Enter на резиденте или авторе показывает его
выпуски, на релизе — его треки, на плейлисте — содержимое. Ещё Enter — играет.
`Esc` возвращает ровно туда, где вы были.

Резиденты — только те, у кого стоит этот статус (их десяток, а не весь каталог
из полутора тысяч артистов). Авторы — только с галочкой. Треки релизов доступны
вошедшим: доступ к ним решает сервер.

**Команды.** `/` открывает строку ввода со списком команд и подсказками:
`/radio`, `/play`, `/pause`, `/search <запрос>`, `/goto <раздел>`,
`/volume <0-130>`, `/mute`, `/back`, `/login`, `/logout`, `/whoami`, `/help`,
`/quit`. Tab подставляет выбранную, Enter выполняет.

**Вход не выходя из интерфейса.** `/login` показывает QR прямо на экране: навели
телефон, нажали Start у бота — личные разделы оживают сразу, без перезапуска.

Три состояния разведены и видны одновременно: какой раздел открыт, какая строка
выбрана и что именно звучит. Поэтому каталог можно листать, не прерывая музыку.

| Клавиши | Что делают |
|---|---|
| `j` / `k`, `↑` / `↓` | по списку |
| `g` / `G`, `PgUp` / `PgDn` | в начало / в конец, на десять строк |
| `Tab`, `h` / `l` | переключение панелей |
| `1` … `9` | сразу в раздел |
| `Enter` | открыть или играть |
| `/` | строка команд со списком |
| `Esc` | назад из карточки |
| `?` | справка |
| `q` | выход |

Клавиши плеера — те же, что на сайте: `space` пауза, `←` / `→` тридцать секунд,
`m` звук, `n` / `p` соседний трек, `r` вернуться в эфир. Расходится одно: `↑`/`↓`
на сайте меняют громкость, здесь ходят по списку — в интерфейсе со списками эта
привычка сильнее. Громкость на `+` и `−`.

## Команды

Для скриптов и быстрых действий всё доступно и построчно:

| Команда | Что делает |
|---|---|
| `surprise` | полноэкранный интерфейс |
| `surprise radio` | играть эфир, показывать что идёт |
| `surprise play <ссылка\|запрос>` | выпуск, трек или релиз |
| `surprise library [раздел]` | плейлисты, лайки, находки, сохранённое, подписки |
| `surprise playlist [название]` | содержимое плейлиста |
| `surprise login` | войти в аккаунт |
| `surprise whoami` / `logout` | кто вошёл / выйти |

`play` принимает и ссылку с сайта, и просто текст:

```bash
surprise play https://surprise.fm/episodes/837393
surprise play shuliko
```

Управление: `space` — пауза, `←`/`→` — перемотка, `q` — выход.

## Вход

По умолчанию — через Telegram. В терминале появятся QR-код и ссылка на бота:
сканируете телефоном или открываете ссылку, жмёте Start, CLI сам получает
сессию.

QR здесь не украшение. Типичный случай — терминал по SSH на сервере, где нет ни
браузера, ни Telegram: кликать некуда, а телефон лежит рядом. По той же причине
флоу не использует локальный порт для redirect — в контейнере и в SSH-сессии
принимать его негде.

```bash
surprise login              # Telegram + QR
surprise login --no-open    # не пытаться открыть ссылку в системе
surprise login --email      # запасной вход по почте
```

Пароль вводится скрыто и не принимается аргументом: аргументы видны в `ps`
другим пользователям машины и остаются в истории шелла.

Сессия лежит в `~/.config/surprise-fm/session.json` с правами `0600`.

## Для скриптов

У всех команд есть `--json`:

```bash
surprise radio --json | jq -r '.now.label'     # что играет сейчас
surprise library likes --json | jq length
surprise whoami --json | jq -r '.supporter'
```

`whoami` возвращает код 1, когда сессии нет, — чтобы `surprise whoami && …` не
считал отсутствие входа успехом.

## Что уходит на сервер

Плеер — клиент surprise.fm, поэтому он общается с `api.surprise.fm`. Список
полный, включая то, что происходит без вашего участия:

| Что отправляется | Когда | Зачем |
|---|---|---|
| Событие прослушивания | после 10 секунд звучания, не чаще раза в полчаса на одну вещь | статистика площадки — те же цифры, что считает сайт |
| Идентификатор слушателя | вместе с прослушиванием трека магазина | квота бесплатных прослушиваний |
| Отметка присутствия | раз в 15 секунд, пока играет эфир | счётчик «сколько сейчас слушают» |
| `x-client-info: surprise-cli/<версия>` | в каждом запросе | отличить терминал от сайта в статистике |

**Идентификатор слушателя постоянный.** Он лежит в
`~/.config/surprise-fm/listener-id`, переживает перезапуски и не привязан к
аккаунту — по нему считается, сколько раз вы уже слушали конкретный трек
бесплатно. Удалите файл — начнётся новый отсчёт, и это единственное, на что он
влияет.

Отметка присутствия и статистика прослушиваний работают **и без входа**: они
относятся к площадке, а не к аккаунту. Если это не устраивает — плеер открытый,
всё перечисленное живёт в `src/api/plays.ts` и `src/api/radio.ts`.

Чего плеер НЕ делает: не ходит никуда, кроме surprise.fm, не собирает
телеметрию об окружении, не отправляет содержимое ваших файлов. Токен доступа
хранится только у вас, в `~/.config/surprise-fm/session.json` с правами `0600`.

## Разработка

```bash
git clone https://github.com/hespermen/surprise-cli
cd surprise-cli
npm install       # только зависимости, сборка отдельной командой
npm test          # чистые функции + обёртка mpv на поддельном процессе
npm run typecheck
npm run build
```

Обёртка mpv проверяется без установленного mpv — поддельным процессом на том же
JSON-IPC (`src/player/fixtures/fake-mpv.mjs`). Так тесты работают в контейнере и
на машине без звуковой карты.

### Переменные окружения

| Переменная | Зачем |
|---|---|
| `SURPRISE_API_URL` | другой бэкенд (по умолчанию `https://api.surprise.fm`) |
| `SURPRISE_MPV` / `SURPRISE_FFPLAY` | пути к плеерам |
| `SURPRISE_BACKEND` | `mpv` или `ffplay` — выбрать плеер принудительно |
| `SURPRISE_SESSION_PATH` | где хранить сессию |
| `SURPRISE_PLATFORM_HINT` | временный обход, пока правка `pickLoginMethod` не на проде |
| `NO_COLOR` | выключить цвет |

### Почему собранный файл лежит в репозитории

`dist/cli.js` закоммичен — это осознанно, хотя обычно так не делают.

Установка из git (`npm i -g github:…`) не может собрать проект сама: при
ГЛОБАЛЬНОЙ установке npm не ставит devDependencies, а без них сборщика нет.
Скрипт `prepare` в этом месте падал с «Cannot find package esbuild», причём
установка при этом рапортовала об успехе и оставляла пустой каталог — команда
появлялась, но не запускалась. Сбой, выглядящий как успех, хуже честной ошибки.

Поэтому в репозитории лежит уже собранный файл, а рантайм-зависимостей у пакета
нет вовсе: всё вкомпилено внутрь, и установка ничего не качает.

Плата за это — дисциплина: после правок в `src/` нужно пересобрать и закоммитить
`dist/cli.js` вместе с ними. `prepublishOnly` подстраховывает при публикации в
npm, но не при обычном коммите.

### Про имена

Их два, и расходятся они намеренно:

| | |
|---|---|
| репозиторий и пакет | `surprise-cli` |
| команда в терминале | `surprise` |

Команду набирают каждый день, имя пакета — один раз при установке, поэтому
короткая форма досталась команде. Совпасть они не могут: имя `surprise` в npm
занято чужим пакетом.

Каталог настроек при этом называется `~/.config/surprise-fm/` — по станции, а не
по пакету. Переименовать его значило бы разлогинить всех, у кого плеер уже
стоит, ради косметики.

### Публикация в npm

```bash
npm publish
```

`prepublishOnly` прогоняет типы и тесты — в реестр не уедет пакет, который не
проходит проверку.

### Чего тут намеренно нет

**`@supabase/supabase-js`.** Нужно около десятка эндпоинтов, а взамен пришлось бы
отдать библиотеке управление сессией — то есть ровно то, что у CLI должно быть
под нашим контролем. GoTrue ротирует `refresh_token`, и обновление здесь идёт под
межпроцессным локом: `surprise` в двух вкладках терминала — обычное дело, а два
параллельных refresh с одним токеном разлогинили бы человека в обоих окнах.

**Свой аудио-декодер.** Нужны Range-перемотка по HTTP, зашифрованный AES-128 HLS
и переподключение к icecast — mpv делает это лучше, чем получилось бы у нас.
